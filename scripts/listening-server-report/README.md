# 一起听服务端排错报告

在一起听歌服务器的项目根目录运行：

```sh
python3 scripts/listening-server-report/collect.py --hours 2
```

`--hours` 支持 1–168 小时，默认 2 小时。脚本需要 Python 3、Docker 和 Compose；仅使用 Python 标准库。
它读取当前 relay/gateway 容器的状态和日志，不调用管理接口，不读取环境变量或 `.env`，不重启服务。

输出到项目内 `misc/diagnostic-reports/`，同时生成 Markdown 和 JSON，默认仅文件所有者可读写。
最多保留 10 组报告，只清理本工具命名的旧报告。报告本身不会自动上传。

报告包含：

- UTC 查询范围、实际可见事件范围、采集失败/截断/日志省略标记；
- 容器运行/健康状态、重启和 OOM、CPU/内存/网络 IO、磁盘余量、主机负载；
- 运行镜像 SHA、容器内与磁盘上的转发源码 SHA-256，便于识别未部署的源码修改；
- 按连接分组的累计音频输入、校验通过、提交转发、无效、无权、错流、限流与拥塞计数；
- 首包超时、断流、恢复、关闭码及原因、最近流编号和事件时间线；
- 网关超时、上游拒绝、DNS 和 TLS 类错误数量，移除完整错误正文和请求内容。

边界：每个容器最多读取 5000 行/8 MiB；每个命令最多等待 25 秒；最多保留 1000 条连接摘要和 300 条时间线。
计数为采集到的生命周期最大值，不能把多份累计快照相加，也不能把房主多音质总包数与单个听众直接比较算丢包率。
容器重建、轮转或采集上限可能导致旧日志不在报告内；缺少异常事件不是无故障的证明。
`forwarded` 只证明服务器提交过发送；对端是否收到、解码、输出，必须结合客户端诊断时间线。

本地回归测试：

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s scripts/listening-server-report -p 'test_*.py' -v
```
